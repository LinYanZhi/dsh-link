## 0. 为什么要建 **TCP 隧道**，而不是 HTTP 隧道

SakuraFrp 官方文档（<https://doc.natfrp.com/faq/site-inaccessible.html>）的建站条件表：

| 节点类型 | HTTP(S) 隧道 | TCP 隧道映射 HTTP 流量 | TCP 隧道映射 HTTPS 流量 |
|---|---|---|---|
| 海外节点 | **需实名认证** | √ | √ |
| 其他节点 | 需实名认证 **+ ICP 备案** | ×（需配置自动 HTTPS） | √ |

TCP 隧道的所有流量**直接透传到本地服务**，不经过"建站"那套 Host/域名判定。
而最终要走的载体 **SSH 本身就是裸 TCP** —— 所以探针也必须说裸 TCP，这样验证结果才能直接迁移到 SSH 场景。

**结论：建 TCP 隧道 + 裸 TCP 挑战应答，绕开建站限制。**

## 1. 前置检查（先做，否则后面白做）

- [ ] **实名认证**：官方 FAQ 明确「使用海外节点穿透其他内容（如游戏联机）**必须进行实名认证**，不需要备案」。实名需 ¥1 + 支付宝刷脸（<https://doc.natfrp.com/faq/realname.html>）。**先登录面板确认你的账号是什么状态。**
- [ ] **免费流量需每日签到**：面板有「点击签到」入口；卡住就多刷新几次（<https://doc.natfrp.com/faq/misc.html>）。流量不足时隧道会被停。
- [ ] **远程端口不能低于 10240**（低于此范围不可用）；**建议留空，让系统自动分配**。
- [ ] **一条隧道只能对应一个运行中的 frpc 进程**（同 ID 重复开会报 `port already used`）。
- [ ] 没有全端口映射 —— 一个服务一条隧道。

## 2. 阶段 1：家里跑握手服务器（10 分钟）

脚本：`handshake-server.mjs`（裸 TCP，零依赖，只绑 `127.0.0.1`）

```powershell
# 家里机，PowerShell
cd <脚本所在目录>
$env:HS_SECRET = "<双方约定的口令>"     # 只走环境变量，绝不写进任何文件/仓
$env:HS_PORT   = "8765"
node handshake-server.mjs
# 期望输出: [probe] handshake server listening on 127.0.0.1:8765
```

**本地自测**（另开一个窗口）：

```powershell
$env:HS_SECRET = "<同一口令>"

```

## 3. 阶段 2：建 TCP 隧道（5 分钟）

在 SakuraFrp 管理面板 → 隧道 → 新建：

| 字段 | 值 |
|---|---|
| 隧道类型 | **TCP** |
| 本地地址 | `127.0.0.1` |
| 本地端口 | `8765` |
| 远程端口 | **留空**（自动分配）或 ≥10240 |
| 节点 | 选一个延迟低的（海外节点也行） |

建好后**记下两样东西**：
- **节点域名 / IP**（隧道页面「节点域名」）
- **远程端口**

然后用启动器（SakuraLauncher）或 frpc 启动这条隧道，日志里要出现 `隧道启动成功`。

## 6. 阶段 5：把方向扳正（通往 `dsh-remote`）

⚠️ **注意方向**：本次验证是「公司 → 家里」。但最终目标是 **`dsh-remote` 让家里的 DSH 操作公司机器 = 家里 → 公司**。所以握手通了之后还有一步：

**方案 A（推荐，零新代码）**
```
家里机：开 SSH 服务端（Windows OpenSSH Server），樱花穿透加一条 TCP 隧道映射 127.0.0.1:22
公司机：ssh -R 2222:127.0.0.1:22 <家里公网端点>     # 公司主动连出，形成反向隧道
家里机：dsh-remote 里把该机器配成 127.0.0.1:2222 → 就摸到公司机的 SSH
```
- 公司只需要**出站**一个 SSH 连接 → 不用在公司开任何入站端口
- 复用标准 SSH 密钥体系（不用自造 token）

**方案 B**：直接在**公司机**跑樱花穿透客户端映射 22 —— 但公司机装 frpc 可能受策略限制，且暴露面在公司侧。

## 7. 安全注意

- `HS_SECRET` 只走环境变量；**不进 git、不进任何文件**（旧仓那个已公开的 `mysecret2026` 就是这么出事的）
- 握手服务器**只绑 127.0.0.1**，由 frpc 本机连接
- 隧道端点暴露公网：**只暴露这一个测试端口**，别把 22 / 3389 / 445 直接挂上去
- **验证完就停隧道**（樱花端点被别人抢到端口时，我们的 `PROOF` 校验能识别出来）
- 隧道是明文 TCP：SSH 自带加密所以无所谓；将来若走非 SSH 协议，要自己加 TLS
