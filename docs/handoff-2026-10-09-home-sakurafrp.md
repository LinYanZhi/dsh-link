## 0. 一句话目标

用**樱花穿透**把家里一个**裸 TCP** 端口暴露到公网，跑一个极小的握手服务器，**异网自测通过**后，把「节点 / 远程端口 / 口令」三样回报给公司侧，由公司侧发起真正的接入验证。

## 1. 背景（为什么这么做）

- 用户的最终目标：**家里的 DSH 能操作公司的电脑**（一个 AI 管多台机器）。已选定路线是装 `dsh-remote` 这类现成插件，走 **SSH**。
- 但 SSH 方向是「家里 → 公司」，而公司机在 NAT 后。所以先要**证明家里能有一个稳定的公网端点**，再谈反向隧道。
- 本次**只做连通性握手验证**，不装插件、不改 DSH 配置。

### 已被公司侧验证过的事实（你不必重做）

| 事实 | 证据 |
|---|---|
| 公司机能连**任意高端口**（不限 443） | `portquiz.net:80/8080/9411` 全部 OPEN |
| 公司机 GitHub / npm 可达 | 200；今天成功 fetch 过 |
| 公司侧握手客户端已双向自测通过 | 好样本 3/3；错口令正确报「PROOF 不匹配」；死端口正确报 ECONNREFUSED |

### 为什么必须用 **TCP 隧道 + 裸 TCP**（不是 HTTP）

SakuraFrp 官方文档（<https://doc.natfrp.com/faq/site-inaccessible.html>）建站条件：

| 节点类型 | HTTP(S) 隧道 | TCP 隧道 |
|---|---|---|
| 海外节点 | **需实名认证** | √ |
| 其他节点 | 需实名 **+ ICP 备案** | 部分场景需自动 HTTPS |

TCP 隧道流量直接透传到本地服务，不经过"建站"的域名/Host 判定。而最终载体是 SSH（也是裸 TCP）——**探针测什么，将来就用什么**。

## 10. 排障速查

| 现象 | 对策 |
|---|---|
| 本地 `127.0.0.1:8765` 就连不上 | 服务端没起 / 端口被占 → 换 `HS_PORT`（如 8766） |
| 面板说「端口不可用（被占用）」 | 换端口，或**留空**让系统分配 |
| 面板说「超出允许端口范围」 | 点远程端口旁「查看规则」，用 ≥10240 |
| 隧道日志报 `port already used` | 同 ID 隧道已在别处跑 → 停掉重复的那个（🛑 先问用户） |
| 日志有 `隧道启动成功` 但连不上 | **换节点**；并确认本地服务在跑 |
| 连通了但响应是 `RESET` / `CONNECTION REFUSED` | 本地服务没起或端口不对 |
| 家里同网通、异网不通 | 换成手机热点再测；仍不通→换节点 |
| 签到卡住 | 多刷新几次；换浏览器（Chrome/Edge/Firefox）；换网络 |
| 出现 503 | 那是 **HTTP 隧道**的问题——确认你建的是 **TCP** 隧道 |
| `PROOF 不匹配` | 端点通了但不是约定那台机（端口被别人占了）或口令不一致 → 核对口令，或换端口 |
| 免费流量用尽 | 去面板签到；必要时买流量（**先问用户**） |
